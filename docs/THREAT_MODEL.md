# Модель угроз

Метод: STRIDE по потокам данных; для каждой угрозы указаны мера, место реализации, проверка и остаточный риск.
Пересматривать при каждом изменении аутентификации, схемы данных, развёртывания или при добавлении
интеграций.

## Активы

| Актив | Почему ценен |
|---|---|
| Личные данные пользователя | задачи, заметки, дневник (в т.ч. настроение), финансовые операции и остатки — чувствительная информация |
| Учётные данные и сеансы | пароли (хеши), refresh-токены (хеши), access JWT, токены подтверждения и сброса |
| Ключи | ключи подписи JWT, сертификат и ключи Data Protection, пароли ролей БД, SMTP-пароль |
| Целостность финансов | баланс должен точно соответствовать операциям; недопустимы дубли и «потерянные» изменения |
| Доступность | сервис и база не должны падать от одного клиента |

## Участники

- **Анонимный посетитель / бот** — может вызывать публичные эндпоинты, перебирать пароли, регистрировать аккаунты.
- **Аутентифицированный пользователь-злоумышленник** — имеет свой аккаунт и пытается получить доступ к чужим данным.
- **Сторонний сайт в браузере жертвы** — CSRF, clickjacking, кража токенов через XSS.
- **Атакующий в сети** — перехват и подмена трафика.
- **Скомпрометированная зависимость или образ** — supply chain.
- **Оператор / резервные копии** — доступ к БД, логам и бэкапам.

## Границы доверия

1. Интернет → nginx (TLS-терминация).
2. nginx → приложение (внутренняя сеть `frontend`; доверяются только заголовки от фиксированного адреса прокси).
3. Приложение → PostgreSQL (внутренняя сеть `backend`, роль с DML-правами).
4. Приложение → SMTP-сервер (сеть `egress`, TLS).
5. Браузер: WASM-код клиента выполняется на устройстве пользователя и считается недоверенным.

## Угрозы и меры

| # | STRIDE | Угроза | Мера | Проверка | Остаточный риск |
|---|---|---|---|---|---|
| T1 | S | Перебор паролей / credential stuffing | лимит 10/мин на IP для auth, блокировка после 8 ошибок на 15 мин, длинные пароли | `Login_attempts_are_rate_limited_*`, `Account_is_locked_*` | распределённая атака с многих IP ограничена только блокировкой аккаунта; CAPTCHA нет |
| T2 | S/I | Перечисление аккаунтов | одинаковые ответы и время для существующих/несуществующих адресов, асинхронная отправка писем | `Registering_an_existing_email_*`, `Login_failures_are_neutral_*` | статистические тайминг-атаки большой выборкой не измерялись |
| T3 | S | Подделка JWT (`alg:none`, чужой ключ, смена алгоритма) | allow-list HS256, проверка подписи, `iss`, `aud`, срока | 8 тестов в `AuthenticationSecurityTests` | утечка ключа подписи → см. T15 |
| T4 | S | Кража refresh-токена | HttpOnly-cookie, хранение хеша, ротация, отзыв семейства при повторном использовании, абсолютный срок 30 дней | `Replayed_refresh_token_revokes_the_family`, `Concurrent_refreshes_*` | вор, использовавший токен раньше жертвы, работает до первого refresh жертвы |
| T5 | S | Использование отозванного сеанса с ещё живым JWT | проверка `sid` на каждый запрос | `Revoked_session_*`, `Logout_*` | — |
| T6 | T | CSRF на refresh/logout | `SameSite=Strict`, `X-CSRF`, проверка `Origin`/`Sec-Fetch-Site`, нет CORS | `Cross_site_refresh_and_logout_are_rejected`, `CsrfTests` | — |
| T7 | I/E | IDOR/BOLA: чтение или изменение чужих объектов по id | фильтр по владельцу в сервисах + глобальный фильтр EF (fail-closed) + составные FK | `DataIsolationTests` (все модули, списки, отчёты, экспорт, ссылки) | ошибка в будущем «сыром» SQL обошла бы EF-фильтр — архитектурный тест запрещает raw SQL API |
| T8 | T/E | Mass assignment (подмена владельца, баланса, версии) | неизменяемые DTO, отказ от неизвестных полей, нет публичных сеттеров | `Unknown_or_protected_fields_*`, `Owner_is_always_taken_from_the_token_*`, архитектурные тесты | — |
| T9 | T | XSS через пользовательский текст | экранирование Blazor, запрет `MarkupString`/`innerHTML`, строгая CSP без inline-скриптов | E2E с `<script>`/`<img onerror>`, `Host_page_policy_*`, архитектурные тесты | уязвимость в самом Blazor/браузере |
| T10 | T | Clickjacking | `frame-ancestors 'none'`, `X-Frame-Options: DENY` | `Api_responses_carry_security_headers_*` | — |
| T11 | T | Formula injection в CSV-экспорте | экранирование префиксов, кавычки | `CsvTests` (включая property-тест) | — |
| T12 | T | SQL-инъекция, инъекция в полнотекстовый запрос | только параметризованные запросы EF; tsquery строится из букв и цифр | `TextSearchTests`, архитектурный тест (нет raw SQL) | — |
| T13 | T | Финансовые гонки, дубли при повторной отправке | идемпотентность, транзакции, `xmin`, баланс из проводок | `Concurrent_edits_*`, `Concurrent_transfers_*`, нагрузочный тест (0 дублей ключей, проводки сходятся) | — |
| T14 | R | Отказ от действий / расследование инцидентов | события `security.*`, correlation id, журнал сеансов | `Passwords_and_tokens_never_appear_in_logs` | нет неизменяемого журнала аудита изменений данных |
| T15 | I | Утечка секретов (репозиторий, логи, образы, `docker inspect`) | секреты вне репозитория, файлы-секреты, gitleaks, Trivy secret scan, логирование без тел и query | gitleaks, Trivy, архитектурные тесты, тест логов | компрометация хоста раскрывает файлы секретов |
| T16 | I | Подделка токенов подтверждения/сброса при доступе только к БД | ключи Data Protection шифруются сертификатом | проверено на production-стенде (`encryptedSecret` в XML ключа) | доступ одновременно к БД и сертификату |
| T17 | I | Утечка через ошибки и заголовки | ProblemDetails с кодом без деталей, `server_tokens off` | `ErrorMappingTests`, `Malformed_json_*` | nginx сообщает `Server: nginx` без версии |
| T18 | I | Перехват трафика | TLS 1.2/1.3, HSTS, Secure-cookie, редирект с HTTP | проверено на production-стенде (TLS 1.1 отклоняется, HSTS присутствует) | соединение с БД внутри Docker-сети без TLS |
| T19 | D | Флуд запросами, большие тела, медленные клиенты | лимиты nginx и приложения, лимит тела 1 МБ, таймауты Kestrel, запросов и SQL | `Oversized_request_body_*`, `RequestBodyLimitTests`, `Deeply_nested_json_*` | лимиты в памяти одного экземпляра |
| T20 | D | Дорогие запросы (огромные страницы, диапазоны, повторения) | ограничения страниц, диапазонов, генерации повторений, массовых операций | `Unbounded_or_excessive_queries_are_rejected` | — |
| T21 | E | Подмена IP через `X-Forwarded-For` для обхода лимитов | доверие только известному прокси; nginx перезаписывает заголовок | `Spoofed_forwarded_for_*`, `Forwarded_for_is_honoured_only_*` | — |
| T22 | E | Повышение привилегий в БД через приложение | роль `pp_app` без DDL, миграции отдельной ролью | проверено на стенде (`permission denied for schema app`) | — |
| T23 | E | Побег из контейнера / запись в образ | non-root, read-only, `cap_drop: ALL`, `no-new-privileges` | проверено на стенде | уязвимости ядра/рантайма |
| T24 | T | Уязвимые зависимости и образы | NuGetAudit, `--vulnerable`, Trivy, Dependabot, digest-закрепление | выполнено локально: 0 уязвимых пакетов, 0 HIGH/CRITICAL с исправлением | новые CVE после сборки — требуют регулярной пересборки |

| T26 | I | Данные удалённого аккаунта остаются в бэкапах | каскадное удаление в БД | `Deleting_the_account_*` | копии хранятся до истечения политики хранения |
