## 1. Ключевые архитектурные решения

1. **Модульный монолит**: `Domain` → `Application` → `Infrastructure` → `Api`; `Contracts` общий для `Api` и `Client`.
2. **Хостинг**: Blazor WebAssembly раздаётся тем же ASP.NET Core приложением, что и API (single origin).
   Это позволяет использовать `SameSite=Strict` cookie для refresh-сессии и полностью запретить CORS.
3. **Аутентификация**: ASP.NET Core Identity (хеширование паролей, lockout, токены подтверждения email/сброса)
   + собственная выдача короткоживущих access JWT (5 мин, HS256 с ключом из секретов, явный allow-list алгоритма)
   + непрозрачный refresh-токен (256 бит) в cookie `__Host-pp_refresh` (`HttpOnly; Secure; SameSite=Strict; Path=/`).
   На сервере хранится только SHA-256 хеш refresh-токена. Ротация при каждом использовании,
   повторное использование → отзыв всей сессии (token family). Access JWT — только в памяти WASM.
4. **Сессии**: таблица `user_sessions` (= token family). JWT содержит `sid`; при каждом запросе
   middleware аутентификации проверяет, что сессия не отозвана (немедленный отзыв).
5. **CSRF**: refresh/logout принимают cookie только при `SameSite=Strict`, обязательном заголовке
   `X-CSRF: 1` (заставляет браузер делать preflight, а CORS закрыт) и проверке `Origin`/`Sec-Fetch-Site`.
6. **Авторизация**: deny-by-default (`FallbackPolicy = RequireAuthenticatedUser`), владелец определяется
   только из проверенного `sub`. Изоляция данных — тремя слоями: явный `WHERE owner_id = @current`
   в каждом запросе сервисов, глобальные query filters EF Core (fail-closed), составные внешние ключи
   `(id, owner_id)` в PostgreSQL, исключающие ссылки на чужие объекты даже при ошибке приложения.
7. **Финансы**: `numeric(19,4)` / `decimal`, двойная запись через `ledger_entries`; баланс = начальный баланс +
   сумма проводок (не хранится и не принимается от клиента). Перевод — одна транзакция с двумя проводками,
   атомарно. Идемпотентность через заголовок `Idempotency-Key` + уникальный индекс. Оптимистическая
   конкуренция через `xmin`.
8. **Время**: `TimeProvider`; UTC-метки — `timestamptz`, календарные даты — `date` (`DateOnly`);
   часовой пояс пользователя (IANA) хранится в профиле, «сегодня» вычисляется на сервере.
9. **Повторяющиеся задачи**: серия (правило) + материализованные экземпляры; следующий экземпляр создаётся при
   завершении текущего; уникальность `(series_id, occurrence_date)` исключает дубли; правка экземпляра не
   меняет серию.
10. **Повторяющиеся операции**: явная идемпотентная операция «провести наступившие» (вызывается клиентом),
    уникальность `(recurring_id, occurrence_date)`; без фонового обработчика, работающего от имени всех пользователей.
11. **Email**: ограниченная очередь (`Channel`, bounded) + `BackgroundService`, SMTP через MailKit;
    локально — Mailpit в Docker Compose. Асинхронная отправка выравнивает время ответа (защита от перечисления).
12. **Rate limiting**: встроенный `Microsoft.AspNetCore.RateLimiting`; ключи — user id (аутентифицированные) или
    IP (анонимные, IP только после `ForwardedHeaders` с явно заданными доверенными прокси).
13. **UI**: один системный шрифт, палитра `#F7F7F5 / #20211F / #8A8D86`, SVG-иконки и SVG-графики без JS,
    строгая CSP без `unsafe-inline`/`unsafe-eval` (только `wasm-unsafe-eval`, необходимый для WebAssembly).
    Локализация интерфейса ru/en.
14. **RLS PostgreSQL**: рассмотрен; см. решение в `docs/SECURITY.md` (раздел «Изоляция данных»).
